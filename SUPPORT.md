# Support

Sextant is maintained by one person at Protechtus LLC, part-time, alongside
running it as a daily driver. Support is best-effort. This page says exactly
what that means so nobody has to guess.

## Where to send what

| You have | Use | Notes |
|----------|-----|-------|
| A bug | Issues, "Bug report" template | Include `sextant-doctor` output if the install works at all |
| A feature idea | Issues, "Feature request" template | Small ideas can go straight to a PR; large ones get discussed first |
| A question, or "is this expected?" | Issues, "Question" template | Check the README, [docs/GETTING-STARTED.md](docs/GETTING-STARTED.md) and [docs/USAGE.md](docs/USAGE.md) first |
| A security problem | The private process in [SECURITY.md](SECURITY.md) | Never a public issue |
| Nothing to report, you just want release notes | "Watch > Releases" on this repository, or email hello@protechtus.com with the subject `Sextant updates` to be told when a release ships | Announcements only; replies there are not a support channel |

Blank issues are turned off. The templates exist so the first reply never has
to be "which OS, which version?".

## What to expect

- Bug reports get an acknowledgement, usually within a few days. That is an
  acknowledgement, not a fix.
- Everything else is read on one weekly triage pass. File on a Tuesday and the
  first response usually lands the following week.
- There is no service-level agreement. Install-breaking and data-loss bugs go
  to the front of the line; everything else waits its turn behind the
  maintainer's own use of the software.
- "accepted" on an issue means it will be worked, or a PR for it will be
  reviewed. It is not a date.
- Issues waiting on information from the reporter (`needs-info`) are closed
  after 14 days of silence and reopened the moment a reply arrives.

## What gets declined

- Feature requests that add a required cloud dependency, a hosted or
  multi-tenant mode, or that cut across the ground rules in
  [CONTRIBUTING.md](CONTRIBUTING.md). They are closed with a note saying why,
  so the idea stays findable.
- Large pull requests that were not discussed in an issue first. They are
  closed with thanks; the discussion is the cheap part, the review is not.

## Forks

Forks are welcome and expected; that is what the license is for. The canonical
project and the Sextant name stay here.
